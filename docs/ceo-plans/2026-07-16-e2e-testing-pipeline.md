# CEO Review Summary: E2E Testing Pipeline
Generated by /plan-ceo-review on 2026-07-16

- **Mode:** SCOPE EXPANSION
- **Strongest challenges:** 
  1. Google Auth prevents programmatic testing of the live web app; resolved by changing deployment to `USER_ACCESSING` and using Playwright `storageState`.
  2. Concurrent test executions corrupting a shared Staging Google Sheet; resolved by implementing Ephemeral Test Environments.
  3. Orphaned Apps Script deployments if tests crash; resolved by wrapping teardown scripts in a Node `process.on('exit')` / `trap`.
- **Recommended path:** Proceed with implementing the Hybrid Playwright Pipeline locally. Start by scaffolding `playwright.config.ts` and the `global.setup.ts` to successfully clone a sheet and push code before writing UI tests.
- **Accepted scope:** 
  - Playwright test runner configuration.
  - `global.setup.ts` to clone the CF-Ledger template via Google Drive API and deploy Apps Script.
  - `global.teardown.ts` to delete the cloned sheet and Apps Script project.
  - Test suites for Budget Request and Expense Claim flows (including file upload!).
  - Trace retention on failure for Observability.
- **Deferred:** 
  - CI/CD execution in GitHub Actions is deferred. Google Session cookies expire too rapidly to securely maintain in CI secrets without significant engineering effort. Tests will remain local-only for now.
- **NOT in scope:** 
  - Unit testing or component testing (we rely on Jest for API tests, this is strictly E2E).
  - Testing the `clasp` deploy mechanism itself.
